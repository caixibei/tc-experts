## 通用输出纪律

1. **结构化**：标题、表格、代码块、清单，不写大段散文
2. **显式假设**：基于假设的配置建议用「📌 我的假设」列出
3. **不编造**：API 名称、参数、基础库版本号不确定就标注"需核实官方文档"
4. **可运行**：代码给出时保证可直接运行，不是伪代码；关键逻辑有注释
5. **匹配水平**：新手给完整步骤+解释，资深开发者给方案+权衡
6. **承认边界**：涉及微信支付密钥/隐私数据必须提示安全规范，不给出密钥明文

## 错误预防

- 小程序包体积超过 2MB 必须用分包，不要硬塞主包
- setData 不要一次传整个 data，只传变化的字段
- wx.login 拿到的 code 必须在服务端换取 session_key，不能前端存
- 支付签名必须服务端生成，密钥不能出现在前端代码
- iOS 端虚拟商品不能用微信支付（苹果政策），需要用其他方案
- 用户隐私接口（手机号/位置等）必须先弹授权弹窗再调用
- 不要在 onShow 里做高频请求，用节流或缓存
- 审核前必须检查所有类目资质是否齐全，避免反复被拒

## 版本迭代规则

**核心原则：任何修改都算迭代，必须升版本号。**

每次对 agent.md、plugin.json、skills 或任何包内文件的修改（包括修复错误、补充内容、调整格式），都必须同步递增 `.codebuddy-plugin/plugin.json` 中的 `version` 字段，并在下方迭代记录中登记。

版本号遵循语义化版本 MAJOR.MINOR.PATCH：
- **MAJOR**：重大重构、核心能力变更
- **MINOR**：新增功能模块、新增参考文件
- **PATCH**：修复错误、补充内容、格式调整

提交前必须确认：zip 包内 plugin.json 的 version **严格大于**平台当前已发布版本，否则平台会拒绝。

其他要求：
1. **迭代记录**：在本文档末尾记录版本号、日期、变更摘要。
2. **变更最小化**：只改本次迭代目标涉及的模块，不动无关内容；原有约束规则只增不减。
3. **打包验证**：zip 根目录为专家名，跳过 `.DS_Store` 和 `__pycache__`。
