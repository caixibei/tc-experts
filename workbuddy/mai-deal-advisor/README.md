# MAI Lab并购交易Agent

版本：1.3.7

体验数据与当前项目概况遵循 `references/project-context.md`：首个有用结果后一次说明、一次选择；默认不含公司名和联系方式，只有用户自愿选择相应范围时才整理允许字段。数据加密存储在上海，项目概况保留 180天，可随时关闭并请求删除；选择不影响继续使用、二维码或联系入口。

项目来了，先把路理清。

**材料可以很乱，交易不能乱。**

客户刚发来一堆材料，不知道先从哪里下手？把可以在 WorkBuddy 中使用的项目资料或项目摘要交给 MAI，先看清这单现在在哪一步、最缺什么、接下来先做什么。

它默认先给一句判断、三项重点和下一步三件事。信息不足时先在对话中快速分诊，不调用工具、不生成文件；资料足够并确认产物后，再进入标准档或深度档，画清交易结构、核对数字和股权比例、整理报告。

要做正式报告时，它会先用几张很短的中文选择卡确认：站在买方还是卖方、项目市场和行业、最想解决的问题、搜索范围、报告深度、给谁看以及交付格式。对话里已经说清楚的内容会直接带入。只有用户确认开工后，才开始搜索、整理和生成文件。

遇到估值、监管或结构设计这类不能硬猜的问题，它会直接标出来。项目需要人工复核或继续推进时，可以联系项目团队。

## 适合谁

- 手上已经有真实项目，但身边缺少完整投行团队支持的 FA 和并购顾问
- 需要快速接住项目的企业战投、融资负责人和交易执行人员

## 它能帮什么

- 判断项目所处阶段，列出资料缺口和下一步三件事
- 默认用精简模式先给结论和 `P0/P1/P2` 优先级，按需切换标准模式或深度模式
- 把已确认的主体、持股、步骤和资金或资产流向画成可编辑 SVG 交易结构图
- 对识别到的标准持股表检查股本分母、股数和比例；缺行、缺值或未识别时明确标为未完成
- 整理一版可继续讨论的报告草稿，并记录关键数字的来源状态
- 正式报告先确认方向，再开始搜索和生成；“你自己决定”不会让它直接进入耗时工作
- 生成表格前后检查表头、列数、口径、来源、合计、股权比例、空值和跨表一致性
- 先交付 Markdown、数据表或 SVG；只有明确要求时才生成并检查 PDF、DOCX 等正式格式
- 可视化先形成结构化中间层，再确定性渲染；PDF/DOCX 先给快速预览，确认后再生成正式成品
- 用 `grounding_gate.py` 拦没有出处或来源层级不够的数字
- 用 `recon_gate.py` 检查持股表分母、重复披露和比例异常
- 用 `hkexnews_fetch.py` 查询港股公告并保留 URL
- 遇到估值、控制权、监管路径等高判断问题时，标明边界并让用户选择是否申请人工复核
- 用户明确当前任务优先；一次回复只保留一个行动号召，依次为当前任务、内置 Skill、明确交易推进的人工入口、普通联系入口；命中前项时不再展示后项
- 内置三个随时可用的工具：交易结构算盘、股权表核验、估值区间快算；有具体交易需求时，在交付分析后提供项目团队联系入口
- 每份正式报告最后一页保留项目团队二维码、邮箱和联系入口，方便报告转发后继续推进

## 它不做什么

- 不包含 MAI 私有判断库、既有项目档案或内部方法；本版不内置云端项目档案
- 不替用户决定交易结构；按既定结构作图可以自动完成，结构设计和优化先形成备选方案，专业结论是否人工复核由用户决定
- 不自动联系外部交易方
- 不处理报价、合同或商业成交安排
- 不把 AI 输出包装成投资建议、证券推荐或法律意见
- 不承接代码开发、复杂调试或工程重构；这类工作建议切换到代码开发专家或 Codex
- 联系项目团队始终由用户自愿选择，专家包不会自动发送对话、文件或项目材料
- 打开联系页面不会自动发送当前对话、文件或项目材料

## 数据边界

- 本公开包没有 Hook，不采集对话、用户文件或生成产物。运行清单、对话正文、项目文件和生成产物内容继续保持 `local_only`，不会因为开启体验数据而回传 MAI。
- 体验数据采用“先用后选”：先交付首个有用结果，再最多显示一次 `references/project-context.md` 的统一四选项；不回答不追问，且不影响任何功能。一次选择对主专家和三个内置技能共同生效。
- 用户开启后，只记录无正文的结构化产品事件，例如使用了哪个能力、从哪里进入、是否完成、是否生成某类产物、耗时区间和错误类别。字段包括协议版本（`schema_version`）、专家与 Skill 标识及版本、去标识化安装标识（`install_id`）、可选会话标识（`session_id`）和固定结果状态。默认不保存提示词或回答全文、公司名、文件名、文件内容或联系方式。
- 三个技能的计算与核验在本地完成。体验数据和主动提交的反馈连接腾讯云上海（中国境内）；不把计算输入或完整材料当作产品事件发送。公司名默认不含，用户选择自愿身份范围时仅按 `references/project-context.md` 白名单整理。
- 反馈以三行对话卡片在结果之后出现：“这次分析帮到你了吗？”用户直接回复“有帮助”或“还差一点”，也可补充一句；系统先展示待提交内容，用户确认后才发送，不要求打开反馈网页。公司、角色、姓名和联系方式均为可选，只有用户另行明确要求联系并提供本人联系方式时才设置联系意向。
- 体验数据、反馈、联系意向和项目档案分别管理。开启体验数据不等于同意保存项目，提交反馈也不等于同意联系。本版只记录已同意的产品事件与主动提交的反馈，不提供云端项目建档。
- 产品事件及其附属项目概况保存 180 天；反馈及其中自愿填写的信息保存 365 天。用户可以随时关闭体验数据，或联系 `ocip@ociphk.com` 申请删除相关记录。
- 联系链接只匿名记录专家包来源与入口位置，用于判断入口是否有效
- 用户是否打开联系页、发送邮件或提交信息，始终由用户自己决定

## 安装

将本目录放置到：

```bash
~/.workbuddy/plugins/marketplaces/my-experts/plugins/mai-deal-advisor/
```

再通过 WorkBuddy 的专家注册流程完成登记。

## 本地校验

交付草稿前，可运行：

```bash
python3 bin/grounding_gate.py draft.md
python3 bin/recon_gate.py cap_table.xlsx
python3 bin/calculation_gate.py draft.md
python3 bin/hkexnews_fetch.py 00700
```

任一 gate 返回退出码 `1`，都代表材料存在拦截项；返回退出码 `2`，代表校验未完成。两者都不能标为 `READY`。

## 依赖

`.txt`、`.md` 和 `.csv` 文件只需要 Python 标准库。扫描 `.xlsx` 需安装 `openpyxl`；扫描 `.docx` 需安装 `python-docx`；扫描文本型 `.pdf` 需安装 `pypdf`。

```bash
python -m pip install openpyxl python-docx pypdf
```
