# 文件接收与产物协议

## 一、接收原则

- 用户提供的源文件只读，不覆盖、不改名、不移动。
- 未授权的保密材料不要上传到 WorkBuddy；可以先提供脱敏摘要、公开材料或字段清单。
- WorkBuddy 能读到文件，不等于包内机器闸门已经校验该文件。回复中必须区分“已阅读”“已提取”“已机器校验”。
- 文件打不开、依赖缺失或内容未识别时，明确写“未完成校验”，不能写“通过”。
- 用户未主动询问本地目录时，不展示绝对工作路径；需要资料时优先说“直接发到本对话”。

## 二、格式适配

| 格式 | 可用于内容整理 | 可进入机器校验 | 处理方式 |
|---|---|---|---|
| `.md` / `.txt` | 是 | 是 | 直接读取；可运行来源和股权闸门 |
| `.docx` | 是 | 条件支持 | WorkBuddy 可读取；机器闸门需要 `python-docx` |
| `.xlsx` | 是 | 条件支持 | WorkBuddy 可读取；机器闸门需要 `openpyxl` |
| `.csv` | 是 | 是 | 按 UTF-8 文本表格读取；可运行来源和股权闸门 |
| `.pdf` | 是 | 条件支持 | WorkBuddy 可阅读文本型 PDF；来源闸门需要 `pypdf`，股权表仍应转成 XLSX/CSV |
| `.pptx` | 是 | 否 | 可整理内容；不能声称已通过包内数字或股权闸门 |
| 扫描件和图片 | 是 | 否 | 可做视觉整理；OCR 结果必须标注，关键数字回到原图人工复核 |

旧版 `.doc`、`.xls` 和加密文件先另存为受支持格式。任何格式转换都生成新文件，源文件保持只读。

## 三、标准产物

快速档不创建文件。只有进入标准档或深度档，且用户明确要求一个可编辑产物时，才使用下列路径；一次最多生成一个当前阶段产物。

所有产物放在当前工作空间的相对目录 `outputs/`：

| 场景 | 标准产物 |
|---|---|
| 项目分诊 | `outputs/project-triage.md` |
| 报告整理 | `outputs/report-draft.md` |
| 报告检查 | `outputs/report-qc.md` |
| 交易结构图 | `outputs/deal-structure-diagram.svg` |
| 结构图说明 | `outputs/deal-structure-diagram-notes.md` |

Markdown 是报告的标准底稿。它必须先包含完整正文、来源状态和待确认项，之后才能派生其他格式。

复杂任务采用渐进式交付：先在聊天中完成范围和优先级，再由用户确认是否生成一个可编辑底稿，检查通过后才生成下一种格式。不得因为用户一次列出多个格式，就同时启动全部生成任务。

## 四、DOCX/PDF 衍生产物

DOCX/PDF 是可选衍生产物。采用“快速预览—正式成品”两段式：先交付已经检查的 Markdown、表格或 SVG 快速预览；用户确认内容后，才可以调用 WorkBuddy 当前可用的文档生成能力，从已经检查的 `outputs/report-draft.md` 生成正式文件：

- `outputs/report-draft.docx`
- `outputs/report-draft.pdf`

只有文件确实存在并完成检查后，才能告诉用户已经生成。至少检查：文件能打开、页数大于零、标题和正文存在、表格没有明显截断、中文没有乱码。

每份正式报告还必须按 `references/report-templates.md` 在最后一页加入“项目继续推进”联系区。二维码使用包内 `assets/project-contact-qr.jpg` 作为源文件，并真正嵌入 DOCX/PDF，不依赖打开文件时再联网加载。导出后检查最后一页、二维码、邮箱和联系链接；二维码缺失、被裁切或无法离线显示时，产物保持 `UNVERIFIED`。

无法生成时，保留完整的 Markdown 标准底稿，说明缺少的工具或失败原因，不得声称已经生成 DOCX、PDF、PNG 或 PPTX。

生成可能等待时，用一句话说明真实阶段；平台没有提供真实进度时不得伪造百分比：

1. `阶段 1/3：已完成范围和目录`
2. `阶段 2/3：正在生成并检查可编辑底稿`
3. `阶段 3/3：正在导出并检查正式文件`

若正式导出失败，不要重复启动同一任务；先交付已完成的 Markdown、数据表或 SVG，再说明失败原因和可选下一步。

## 五、报告质检记录

创建 `outputs/report-qc.md`，至少记录：

```markdown
# 报告质检

## 已读取文件
## 未读取或转换失败的文件
## 已机器校验的范围
## 数字与出处问题
## 股权勾稽问题
## 结构化自检（表头、列数、口径、合计、空值、跨表一致性）
## 待确认事项
## 产物清单与格式状态
```

“已机器校验的范围”要写清文件格式、脚本名称和退出状态。没有运行机器闸门时，不能用“已核验”描述结果。

结构化自检不等于事实核验。回复中分别标明 `已校验`、`待确认` 和 `未完成`；存在列错位、口径冲突、合计错误或跨表不一致时，不得标为 `READY`。
