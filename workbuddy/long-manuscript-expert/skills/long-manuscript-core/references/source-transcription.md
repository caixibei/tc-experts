# 来源忠实转录

来源忠实转录不是润色或代写。目标是让每一页的来源身份、机器观察、人工核对、修正依据和最终快照可区分、可复核。

## 平台中立边界

包内运行时不读取图片、PDF或工作区文件，不启动 OCR，不调用网络，也不写文件。调用方只能把已有的页描述、摘要和文本观察交给运行时；真实图像读取、OCR执行及最终保存属于宿主边界。

所有输出固定声明：

- `actualOcrExecutionAllowed=false`
- `ocrExecutionPerformed=false`
- `hostMutationAllowed=false`
- `externalActionCount=0`

页清单中的 SHA-256 是调用方提供的绑定，证据等级为 `digest_supplied_not_observed`，不能写成包内已经观察了源文件字节。

## 七步流程

1. 建立连续且唯一的页清单，明确主来源、页码依据、方向和风险。
2. 接收调用方提供的只读文本观察，保留为 `ocr_raw` 快照。
3. 把机器观察与来源人工核对分开；未经核对的页保持 `ocr_extracted_unreviewed`。
4. 对稀疏、密集、版式风险三类代表页建立人工抽样记录。
5. 把疑似乱码、OCR碎片、罕见词、数字单位冲突和跨页边界登记为独立问题。
6. 来源裁决只接受带 `sourceRef` 与 `sourceReading` 的决定。
7. 修正通过不可变快照的内存补丁完成；宿主决定是否把新快照保存到文件。

页面覆盖、页序、方向、原始观察、抽样和三项来源忠实门均通过后，状态最多为 `delivery_ready`，含义是“可交给宿主保存”，不等于文件已写入或已经交付。

## 转录执行流程（26.9.18 由 agent md 迁入）

> 本节是 `source_transcription` 与 `review_quality:transcription_comparison` 的完整执行步骤。当用户要求扫描页、逐字稿、来源恢复、OCR 结果核对或两个转录版本比较时，**不得把它当作普通润色**。

来源忠实转录依次执行：

1. 建立连续页清单，确认每页主来源、页码依据、方向和风险。
2. 优先消费当前 WorkBuddy 会话实际呈现的图片、页面渲染、文档文本或表格结果；若当前表面没有交付这些内容，再接收调用方提供的文本观察。不得从文件名、附件卡片或模型能力标签推定正文已经读取。
3. 按实际来源选择处理层，**不能因输出了文字就新增 OCR 层**。仅模型看图形成的转录全部属于 `visual_observation_raw`，状态为 `observed_unreviewed`；不得标成 `ocr_raw` 或 `ocr_extracted_unreviewed`。只有真实 OCR 工具结果或用户明确提供的 OCR 输出，才可使用这两个 OCR 标签，并绑定工具/提供者与来源；文档解析、表格抽取也须有对应结果。普通文稿优先写“模型看图形成的候选转录，未经独立 OCR 核对”，不必输出内部状态码。交付前检查记录头和处理层是否一致，不能一边说无 OCR、一边标为 OCR 产物。
4. 由人工对来源进行核对，并覆盖稀疏、密集、版式风险三类代表样本。
5. 运行 `page-sequence.integrity`、`transcription.fidelity`、`ocr-artifact.suspect` 三门。
6. 对不确定字符、罕见词、数字单位和跨页边界建立问题；**不得自动选择更顺畅的读法**。
7. 来源修正必须带 `sourceRef` 和决定依据，通过内存补丁生成新快照。

比较多稿时，**相似度只用于定位差异**。优选版本来自用户显式选择、唯一 current 标记或唯一较高语义版本；这些信号仍不能替代来源裁决。差异未绑定来源图像/页引用和人工决定时，状态保持 `human_review_required` 或 `human_review_pending`。

`externalToolsAvailable` 是输入声明，不是工具发现、授权或执行证明。无论它是 `true` 还是 `false`，都不能触发 OCR、外部端口、网络调用或写盘。WorkBuddy 系统自动分配的 `Read` 等工具或宿主已呈现的附件可以在当前任务中使用，但必须以真实返回内容和当前回执为准；既有可选端口仍只能经过独立适配合同、当前授权和回执链。
