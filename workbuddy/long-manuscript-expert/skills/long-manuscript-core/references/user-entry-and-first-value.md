# 五个用户入口与首轮首值

26.9.10延续并升级五个稳定用户入口。WorkBuddy公开面仍保留官方要求的三条快速提示：第1条组合材料启动与来源忠实转录，第2条组合项目继续与限定范围改稿，第3条用于成稿收口。组合提示必须根据用户材料和信号选择一个入口，不能同时混做两个工作流。

| 入口 | 选择信号 | 首轮必须交付 |
|---|---|---|
| `material_start` | 提纲、笔记、访谈、零散材料、从零启动 | 可编辑手稿启动结构；至少一段实质开篇；唯一下一步 |
| `source_transcription` | WorkBuddy当前可见的扫描页/图片/页面渲染、逐字稿、来源恢复或调用方提供的OCR文本 | 可编辑页图或问题表；实质忠实转录；唯一下一步 |
| `project_resume` | 继续项目、续接胶囊、项目状态或检查点 | 可编辑续接卡；从对齐锚点写出的实质下一段；唯一下一步 |
| `bounded_revision` | 只改某段、某节或选区 | 可编辑范围/变更图；实质改后正文；唯一下一步 |
| `finished_draft_closure` | 成稿、终稿、交付前检查 | 可编辑收口清单；最高价值问题的实质替换文本；唯一下一步 |

首轮不得只返回问题、计划、空模板或能力介绍。最多提出一个会实质改变结果的阻塞问题；其他缺口以明确、可撤销的假设处理。

## 项目继续不是只读旧胶囊

旧 `ContinuationCapsule` 保持兼容，仍承担用户可复制的文档定位、稳定锚点、锁定约束、证据缺口和下一目标。26.9.10 的 `project_resume` 还必须在可用时组合：

- `ProjectStatus`：当前项目阶段、章节进度、门状态和阻塞；
- `ChapterCheckpoint`：最近一个可验证章节停点及内容摘要；
- `FactDelta`：自上次稳定状态后新增、修正或冲突的事实；
- `ManuscriptObjectiveBinding`：用户可见的目标、验收条件和所有者；它不是宿主 Goal。

输出 `ProjectResumeCard` 前，比较这些对象的摘要和状态。证据缺失时仍可依据用户再次提供的旧胶囊继续，但必须标为 `capsule_only`，不能声称加载了隐藏项目状态。证据冲突时先给最小可编辑续接图和一个阻塞问题，不静默选择任一版本。

## 回执和外部动作

没有当前回执时，所有机器结论默认为 `advisory`。快速提示、注册表、开发测试或历史回执不能替代当前任务回执。

福帮手连接器（`fbs-connector`）是本产品的准入声明项，但**五个入口的首值都不依赖连接器的当前可用性**；连接器只影响可选增强动作，且不改变场景路由。`externalToolsAvailable` 只是一项声明；不会自动启动OCR、网络、企业微信/FBS端口或文件写入。WorkBuddy 当前任务实际呈现的附件或系统分配工具的成功返回可以成为本次输入，但必须与模型声明、OCR/解析和外部动作分层。真实外部动作、宿主保存与发布必须由独立授权表面执行并回传当前回执。

本入口合同不证明官方上架、真实宿主激活、外部服务成功或业务闭环。
