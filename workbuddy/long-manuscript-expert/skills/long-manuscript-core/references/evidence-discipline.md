# 证据纪律：主张、来源、冲突与反证

> 何时读我：整理真实材料、核验主张、处理来源冲突、做外部查证，或需要判断“一条证据能不能单独过门”时。
> 26.9.18 吸收自 `industrial-park-investment-attraction-expert` 的 entity-evidence-audit 与 `fbsir-industry-scene-researcher` 的 evidence-and-conflicts，按长文档写作场景改写。

## 1. 证据标签：七级，且不得相互晋级

| 标签 | 含义 |
| --- | --- |
| `source_fact` | 一手来源直接陈述的事实 |
| `company_claim` / `subject_claim` | 主体自述或宣传口径 |
| `independent_observation` | 独立第三方观察 |
| `user_statement` | 用户提供的陈述 |
| `inference` | 由已知推出的推断 |
| `hypothesis` | 尚未验证的假设 |
| `unknown` | 未知 |

**不得相互晋级。** 推断不能因为反复出现变成事实；主体自述不能因为措辞确定变成一手事实；独立观察不能替代原始文件。

## 2. 主张字段（claim）

每条主张至少包含：

```
claimId / predicate / value / normalizedValue / valueType / unit
validFrom / validTo
evidenceRefs[] / sourceUsageAssessments[]
freshnessStatus / conflictGroupId / alternativeExplanation
```

`sourceUsageAssessment` 必须带 **`usageEligibility`**：

| 取值 | 含义 | 使用限制 |
| --- | --- | --- |
| `standalone` | 该来源可单独支撑主张 | 可以单独过门 |
| `corroborative` | 只能作为补充 | **不得单独过门**，也**不得被固定成“必须两条来源”的全局规则** |

> 关键纪律：**不存在“必须两条来源”这种全国统一规则。** 是否可单独过门取决于该来源对这条主张的适用性，不取决于来源数量。

## 3. 四值判定

| 判定 | 处理 |
| --- | --- |
| `supports` | 关键主张计入证据门时必须为 `supports` 且来源可回读 |
| `partially_supports` | **只可作为观察或待核验信息**，不得计入证据门 |
| `contradicts` | 进入冲突组，不得静默丢弃 |
| `unknown` | **不是反证。** 标记 unknown 并给出精确补证任务，不把资料缺口写成事实反证 |

## 4. 冲突处理

**冲突不能靠多数票自动消失。** 出现冲突时逐项记录：

1. 口径差异（同一概念的不同定义）
2. 时点差异（不同期间的有效值）
3. 当前采用哪个解释、理由是什么
4. **什么新证据会改变当前结论**

同一冲突用 `conflictGroupId` 归组，用 `alternativeExplanation` 记录未被采纳的另一解释。

## 5. 来源独立性

- 每条来源必须带 `sourceFamilyId`。
- **同源转载、同一稿件衍生、图表或 OCR 摘要仍属同一来源家族**，不增加独立性。
- 相互印证要求来自**不同家族**；同一家族的多份材料不得当成多条独立证据。

## 6. 实体归一：先闭包，再合并

处理主体身份时：

1. **先对每个候选独立完成身份闭包**，再根据已验证的稳定键判断是否同一主体。
2. **不能用固定字段顺序提前合并**，也不要按名称相似度先合并再找依据。
3. **品牌名不能单独作为主体键。**
4. 统一社会信用代码需校验校验位；域名需去协议、端口、路径与尾点后再比较。
5. 无法生成稳定键时不得强行生成。
6. 无法消歧时标 `ambiguous`，不进入合格池。

## 7. 按主张绑来源（不用全局来源排名）

**不存在一张对所有主张都有效的全局来源排名。** 先明确要证明什么、证明哪个时间点、涉及哪个主体和属地，再选适用来源。

- “只使用这些来源”是**硬限制**；“优先使用”允许在明确标注后补充。
- 优先一手：机构原文、监管或政策原文、论文与数据集、具名客户材料。
- 新闻与聚合页用于线索；**搜索摘要不充作正文证据**。
- 来源数量不是质量；**不得按来源数量投票**。
- 动态页记录读取日期；无发布日期标 `unknown`；时效性事实在交付前复查。
- 陈旧来源可用于历史背景，**不能独立支持当前关键状态**。

按主张类型选来源的对应表见 `05-ops/search-policy.json` 的 `claimTypeToSourceHint`。

## 8. 反证与收齐

- 反证族独立成组：主体状态（注销/吊销/破产/失信/停业）、项目状态（终止/延期/停产/缩减/撤回）、合规（处罚/诉讼/监管问询）、组织（裁员/核心人员流失/股东变更）。
- **重要反证必须与支持材料同等可见**，不得放入不可见附录、脚注或折叠区。
- 收齐口径四字段：`expected` / `returned` / `failed` / `missing`。
- **只有关键分支实际返回或明确结算，才能称研究收齐。**
- 数量是工作预算，不是凑数目标。
- 失败分类：`not_found` / `access_denied` / `timeout` / `parse_failed` / `tool_unavailable` / `source_conflict`。换路必须保持原来源范围。

## 9. 与事实门的关系

本文件的判定结果进入 `frontstage-p0-gates.md` 的“来源到正文的事实门”：

- 只有 `supports` 且可回读的主张才能写进正文事实段。
- `partially_supports` 与 `unknown` 只能写成待核验表述，措辞取自 `../assets/statement-patterns.json`。
- 冲突未裁决时，正文保留冲突双方口径，不得择一叙述。

## 证据边界

本文件是包内纪律，**不执行搜索、不验证来源真实性、不构成事实核验**。它约束的是“我们如何记录与叙述证据”，不是“证据本身是否为真”。
