# 能力预检与来源边界

能力预检先区分必需能力、可选能力、已观察能力、拒绝信号和用户明确接受的降级。降级可以让任务继续，但不能证明原能力已经运行；原能力必须保留在 `cannotClaim` 中。

## 四种观察状态

- `bytes_observed`：当前运行确实拿到了材料字节，可以声明读取了这些已提供字节。
- `summary_observed`：只观察到摘要，不能声明读取了全文。
- `digest_supplied_not_observed`：只收到摘要值，不能声明独立读取或复算了内容。
- `descriptor_only`：只有名称、类型或定位描述。

`ArtifactProvenance` 必须保留观察状态、来源引用、推断引用、父工件摘要和交叉验证层级。推断不能升级成来源观察；摘要存在也不能升级成字节已观察。

## 失败和部分成功

- 缺少未被接受降级覆盖的必需能力：`blocked`。
- 必需能力由用户接受的替代能力覆盖，或只有可选能力缺失：`degraded`。
- 衍生产物一部分可计划、一部分不可用：`partial`，逐项保留原因。
- 评审简报始终为建议性只读对象，不修改正文，也不把建议包装成机器质量结论。
