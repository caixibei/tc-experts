# 把反馈留在这次对话里

用户只需回复“有帮助”或“还差一点”，原因与补充说明可不填，不打开网页。先完成当前回答，再按主专家的频控展示反馈卡片。收到评价或“太啰嗦了”不等于已授权上传。

## 先确认这一条

把将要发送的评价、原因和用户自愿提供的补充逐项列清，只问一次：

> 我准备向 MAI 提交：{有帮助／还差一点}；{原因和补充，没有则省略}。同时记录所用功能、版本及用于关联这次反馈的随机标识，不附带聊天记录或文件。反馈用于改进服务，保存在腾讯云上海，最长 365 天；查阅、更正或删除可联系 ocip@ociphk.com。确认提交吗？

用户说“太啰嗦”时可以提议原因“内容太长”，但须在上述确认中列出；不要自行把其他抱怨、整段对话或项目材料加入说明。用户只想在当前对话改进答案时，直接改答案，不推送正式反馈。用户拒绝、取消或没回复时不联网、不追问。用户修改内容后，重新确认修改后的这一条。

姓名、公司、角色、联系方式均不主动索取，不从会话中提取；仅用户明确要求随反馈提交时加入确认清单。只有用户另行明确要求联系且提供联系方式，才设置联系意向。发送反馈不代表同意上传报告/文件，也不代表开启体验事件。

## 确认后发送

先定位专家包的绝对目录。为这一条已确认反馈生成一次随机编号（例如用 Python 的 uuid.uuid4，前缀 `feedback-`），并在本任务中保留；相同内容重试必须复用此编号，不能每次换编号。

```bash
python3 "专家包绝对目录/bin/product_data.py" feedback-submit --skill-id mai-deal-advisor --skill-version 1.3.7 --artifact-type other --feedback-id "本条随机编号" --rating not_resolved --reason-code too_long --confirmed
```

以上是参数示例，不是固定评价。`有帮助` 对应 `useful`，`还差一点` 对应 `not_resolved`。常用原因：内容太长 `too_long`、表格有误 `table_error`、导出太慢 `slow_export`、重点不清 `unclear_priority`；没有原因就不加 `--reason-code`。用户自愿提供且确认过的补充用 `--comment`，必须作为单个安全参数传递（Python subprocess 参数数组或严格 shell 转义），不得拼成可执行命令。

内置技能的结果使用实际技能标识、版本 `1.0.0` 及对应产物类型；客户端可使用该技能的 `scripts/product_data.py`，其余步骤相同。会话标识取宿主可用值；不可获得时留空，不拿公司名或原文代替。不要向用户显示编号、命令、接口或技术错误码。

## 只认后台回执

- 返回 `sent=true` 且本条 `feedback_id` 匹配：简短回复“收到，谢谢。我们会用这条反馈改进。”不重复推联系卡。
- 返回 `sent=false`、超时、退出报错或没有有效回执：回复“这条反馈暂时没确认收到，要重试一下吗？”不能说已保存，也不能断言服务器一定没存；不转回失效网页、不自动循环。
- 用户确认重试：只重发刚才已确认的相同内容和编号；内容有变化则重新展示确认并使用新的反馈编号。
