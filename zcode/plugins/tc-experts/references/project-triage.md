# 并购项目分诊工作流

本工作流把一堆尚未整理的项目材料变成下一步可以执行的工作底稿。先使用用户已经提供的内容，再按 `references/response-and-quality-contract.md` 给出判断、优先级和最少追问。

## 一、启动规则

1. **先读用户已经提供的内容**：消息、附件、文件名和已有表格都算输入，不要让用户重复填写材料中已经明确的信息。
2. **只追问仍会影响首个产物的事实**：默认每轮最多提出一个决定性问题；能够标为 `[待确认]` 而继续推进的，不阻塞首轮产出。新建正式报告或启动深度研究是例外，改用 `references/report-intake.md` 的短选择卡；已经明确的内容不得重复询问。
3. **快速档先在聊天中分诊**：信息不足时先在聊天中完成快速分诊，不调用工具或脚本，不得生成分诊文件。即使用户同时点名 PDF、DOCX、报告或全部产物，也保持快速档。
4. **标准档才写文件**：只有关键输入足以支持一个可编辑产物，且用户明确要求保存或生成该产物时，才生成 `outputs/project-triage.md`；一次最多一个产物。
5. **不替用户拍板**：估值方法、结构选择、控制权、监管路径、税务和牌照问题只标明决策点。

## 二、项目阶段

按现有证据选择一个主阶段；无法确定时写“待确认”，并说明缺少哪项事实。

| 阶段 | 判断信号 |
|---|---|
| 机会识别 | 只有公司、赛道或初步交易想法 |
| 项目定义 | 已明确买方或卖方角色、目标和交付物 |
| 资料与分析 | 正在收集公开资料、财务、股权和行业信息 |
| 方案讨论 | 已有估值、结构、融资或监管路径草案 |
| 材料准备 | 正在制作内部备忘录、报告、结构图或审批材料 |
| 交易推进 | 已进入接触、尽调、谈判、签约或交割 |

## 三、标准交付物

标准档或深度档需要保存分诊底稿时，创建 `outputs/project-triage.md`，严格使用以下结构：

```markdown
# 项目分诊

## 一句判断
{项目现在意味着什么、为什么先做当前动作}

## 最重要的三项
- P0 当前阻断项：{没有则省略}
- P1 显著影响项：{没有则省略}
- P2 优化项：{没有则省略}

## 项目所处阶段
阶段：{阶段或待确认}
判断依据：{来自用户材料的事实}

## 现有资料
| 资料 | 已获得/待确认 | 可以支持什么 |
|---|---|---|

## 关键缺口
| 缺口 | 为什么影响下一步 | 获取方式 |
|---|---|---|

## 下一步三件事
1. {动作、负责人或输入、产物}
2. {动作、负责人或输入、产物}
3. {动作、负责人或输入、产物}

## 可立即生成的产物
- {产物名称、格式、所需输入}

## 需要专业判断的事项
- {决策点；没有则写“本轮未识别”}

## 待确认
- {不阻塞首轮工作的未知项}
```

“下一步三件事”必须是当前阶段最先发生的三项动作，不能写成泛泛建议。每项至少说明需要什么输入和会形成什么产物。

快速档只在聊天中展示“一句判断、最重要的三项、下一步三件事和最多一个必要问题”，不创建任何文件。进入标准档或深度档后，完整资料表、缺口表和边界记录才保存在 `outputs/project-triage.md`。

## 四、继续推进

分诊完成后，根据用户选择进入相应工作流：

- 结构已确定，需要作图：调用 `references/deal-structure-diagrams.md`。
- 需要整理报告：先调用 `references/report-intake.md` 完成开工确认，再调用 `references/report-templates.md` 和 `references/file-intake-and-output.md`。
- 需要检查数字或股权表：调用包内相应 gate，并按退出码解释结果。
- 需要高判断事项：先整理决策材料；是否找MAI团队，由用户决定。
