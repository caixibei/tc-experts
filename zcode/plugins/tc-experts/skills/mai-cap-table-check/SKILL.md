# 股权表核验

**每一股都对上，每一次变化都有来路。**

股权表最危险的，不是少一行，而是每一行看着都对，分母却不是同一个。上传一张股权表，先看它能不能拿去谈。

一次使用会先回答“这张表能不能继续用”，再给出股本分母、明细合计、疑似重复披露、交易前后变化和待核实事项。结果只核验表内算术和用户明确提供的变化，不把算术通过包装成控制权、并表或监管结论。

## 什么时候使用

以下任务直接使用：

- “帮我看看这张股权表对不对”；
- “每一行比例是不是用了同一个股本分母”；
- “总计行和明细为什么对不上”；
- “自然人和持股公司两行是不是重复算了”；
- “增资前后每名股东被稀释了多少”；
- “交易前后总股本为什么差了这一截”；
- “这份股权表现在能不能放进交易方案”。

以下任务转向相邻产品：

- 需要比较增资、老股转让、现金与股份支付方案，转入「交易结构算盘」；
- 需要判断合理价格区间，转入「估值区间快算」；
- 需要完整交易建议、控制权分析或正式交付，转入「MAI Lab并购Agent」。

每轮只推荐当前最相关的一个下一步；不叠加第二个推荐，不展示完整产品菜单。

## 两种入口

### 单表体检

用于核验一张或同一文件内多张明确股权表：

- 股东名称、股数和持股比例是否完整；
- 股数与比例是否使用同一分母；
- 明细与总计是否一致；
- 比例合计是否明显超过百分之百；
- 是否存在同名重复行；
- 是否存在疑似重复披露或包含关系；
- 公式显示值能否与独立复算结果对上。

### 交易前后对表

用于对比两张明确标注的交易前、交易后股权表：

- 总股本增加或减少了多少；
- 每名股东股数和比例如何变化；
- 哪些股东股数不变但被稀释；
- 哪些名称是新增出现或不再出现；
- 新发行、回购或注销股份能否解释总股本变化；
- 前后名称是否需要用户确认对应关系。

不要根据文件创建时间猜测交易前后顺序。名称不同也不得自动认定为同一主体。

## 最少输入

### 单表体检

至少需要一张包含“股东或持有人、股数、持股比例”的可识别表格。优先确认：

- 数据时点；
- 分母名称，例如已发行股份、完全稀释股份或有表决权股份；
- 明确股本分母；
- 来源或原始文件位置。

### 交易前后对表

至少需要：

- 明确的交易前表；
- 明确的交易后表；
- 交易前总股本；
- 交易后总股本；
- 如总股本变化，新发行股份和回购或注销股份数量。

用户不知道的内容可以标为“暂不明确”。只有缺少内容会改变核验状态时才追问，一次最多提出三个问题。不得自行补数字、猜分母或推断股份行为。

## 本地核验

### 单表体检调用

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/mai-cap-table-check/scripts/check_cap_table.py" snapshot "用户文件路径" \
  --denominator-name "已发行股份" \
  --declared-denominator "100000000" \
  --as-of "2026-08-30"
```

### 交易前后对表调用

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/mai-cap-table-check/scripts/check_cap_table.py" compare \
  --before "交易前文件路径" \
  --after "交易后文件路径" \
  --before-denominator "100000000" \
  --after-denominator "120000000" \
  --issued-shares "20000000" \
  --cancelled-shares "0"
```

只有用户明确确认两种名称属于同一主体时，才加入名称对应参数：

```bash
--alias "张三=张三先生"
```

程序参数属于机器标识，不向用户展示。用户看到的产品名称、状态、问题和建议始终使用中文。

支持 Excel、Word、CSV、Markdown 和表格化纯文本。图片、扫描件或连续自然语言不能可靠识别时，请用户粘贴表格，不从文字中猜出一张股权表。

## 三种结果状态

### 可以继续使用

目标表格均被识别，关键字段完整，股数、比例、合计和交易前后变化能够闭合，也没有未解决的口径混用或疑似重复披露。

若未确认分母性质，必须追加“仅完成算术口径核验，分母性质待确认”。

### 修正后再使用

存在明确的算术矛盾，例如：

- 股数、比例与明确分母不一致；
- 明细与总计不一致；
- 比例明显超过百分之百；
- 同一股东名称重复出现；
- 交易前后股份桥接不闭合；
- 数值、单位或公式结果互相矛盾。

### 尚未完成核验

表格未识别、关键数据缺失、文件损坏、公式结果不可读取、权益口径混用、疑似重复披露未核实、名称无法对应，或总股本变化缺少解释。

不得把“未发现问题”和“没有完成核验”混为一谈。

## 必须守住的边界

- 直接持股、实益持股和表决权分别核验，不自动相加；
- 相同或接近股数只形成“疑似重复披露”，不直接宣称重复计算；
- “交易后新增出现”不自动等同于获得新发行股份；
- “交易后不再出现”不自动等同于退出；
- 分母算术一致不等于分母的法律性质正确；
- 百分之五十一不自动等于实际控制；
- 算术核验通过不等于事实来源正确，也不等于交易具备决策条件；
- 不自动修改或覆盖用户原文件。

具体舍入、分母和桥接规则见 `references/核验口径与证据规则.md`。

## 结果怎么说

第一屏先回答“能不能继续用”，不先展示程序日志或大段方法说明。

单表体检按以下顺序：

1. 一句话结论；
2. 使用建议；
3. 分母与时点；
4. 必须修正；
5. 需要核实；
6. 关键复算；
7. 最多两个下一步；
8. 符合下方频控时展示反馈入口。

交易前后对表按以下顺序：

1. 一句话结论；
2. 使用建议；
3. 总股本变化；
4. 股东逐项变化；
5. 稀释与新增持股；
6. 未解释差额；
7. 需要核实；
8. 最多两个下一步；
9. 符合下方频控时展示反馈入口。

每个问题都要说明所在位置、发现、影响和建议动作。不能只说“分母不一致”，还要列出相关行的隐含分母。

## 简短结果优先

用户只要求算几个数字或快速核对时，结果主体只给一句结论、一张必要的小表和最多一个关键假设，正文以 250 个中文字符以内为目标（表格数字除外）。不机械套用多个章节、三项重点及三项下一步，不新增未请求的混合方案或敏感性情景。复杂问题才按前文完整结构展开。反馈或数据选择至多附加一个。

聊天表格输出前逐行自检：每行单元格数量必须与表头一致，不使用合并单元格，不插入只有一个单元格的跨列说明行；说明写在表外。只列必要的结果列，长解释放在表外，避免聊天窗口横向溢出。表内每个结果带明确金额或股份单位。此项是模型格式自检，不得冒充机器校验。
