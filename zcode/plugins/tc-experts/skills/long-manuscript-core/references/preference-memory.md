# 偏好沉淀：文风、人称、篇幅

> 何时读我：用户反复给出同一类写作偏好时；或需要判断某条偏好是否该固化为项目约束时。
> 26.9.18 吸收自 `tietu-toutiao` 的 preference-memory 规则。

## 1. 优先级

偏好冲突时按此顺序取用：

```
明确指示  >  固化偏好  >  倾向偏好  >  默认
```

- **明确指示**：用户本次明确说的。永远优先。
- **固化偏好**：经确认、多次出现的稳定偏好。
- **倾向偏好**：观察到但只出现过一次的倾向。**只作为默认值，可被任何指示覆盖。**
- **默认**：包内写作标准。

## 2. 固化规则

| 规则 | 说明 |
| --- | --- |
| 每次最多沉淀 1 条 | 一次记录多条会淹没真正重要的偏好 |
| 复述确认 | 写入前先复述给用户：“我记下你偏好 X，对吗？” |
| ≥2 次才固化 | 只出现一次的观察留在“倾向偏好”，不升级 |
| 20 行上限 | 超出时合并或淘汰最旧、最少使用的条目 |
| `superseded` 不删除 | 被新偏好替代的旧条目标记替代，**保留** |
| 冲突时取更具体 | 两条偏好冲突时，取范围更窄、更具体的 |

## 3. 可沉淀的偏好类型

| 类型 | 示例 |
| --- | --- |
| 文风 | 少用形容词；句子偏短；不用感叹号 |
| 人称与视角 | 第一人称叙述；不用“笔者” |
| 章节长度 | 每节 1500–2500 字 |
| 术语选择 | 统一用“传主”不用“主人公” |
| 标点与格式 | 中文全角引号；不用破折号连接分句 |
| 称呼 | 对某位人物固定用某个称谓 |

## 4. 不可沉淀的内容

**偏好记忆不是事实存储，也不是项目状态。** 以下不进偏好：

- 材料中的事实、日期、人名、数字 —— 属于来源账本
- 项目进度、章节完成状态 —— 属于项目状态
- 模型自己提出的目录、体例建议 —— 属于“模型暂定”，未经用户确认不得晋级为偏好
- 密码、Token、Cookie、私钥等凭据 —— **任何情况下都不记录**
- 一次性任务的临时要求（“这次先写 800 字”）

## 5. 与三态的关系

偏好条目同样使用三态：

- `用户已确认`：用户明确说过，或经复述确认
- `模型暂定`：模型观察到的倾向，未确认
- `未知`：不清楚用户偏好

**模型观察到的倾向永远留在“模型暂定”，不得因为反复出现就自行晋级。** 反复出现只提高“值得向用户确认”的程度，不构成确认本身。

## 6. 应用方式

- 偏好影响**表达**，不影响**事实**。任何偏好都不得导致事实被改写、限定语被删除或证据状态被升级。
- 偏好与来源约束冲突时，**来源约束优先**。
- 用户临时指示与固化偏好冲突时，**临时指示优先**，并在本轮说明“这次按你的临时要求，之前记的偏好没变”。

## 7. 检查清单

- [ ] 本轮最多新增 1 条
- [ ] 新条目经复述确认
- [ ] 观察类条目留在“模型暂定”
- [ ] 未把事实或项目状态写进偏好
- [ ] 未记录任何凭据
- [ ] 替代关系用 `superseded` 标记，旧条目未删除
- [ ] 总行数 ≤20

## 证据边界

偏好记忆只描述**用户对表达方式的倾向**，不构成事实依据，也不改变任何证据状态。写入偏好不等于系统已持久化；只有当前任务中出现真实的写入回执，才能声称已保存。
