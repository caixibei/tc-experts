# 媒体索引与内容证据

本工具用于先把大批视频变成可查询的素材目录。元数据索引是有效交付，不要求每轮都立刻生成章节；下一步仍须服务于用户的写作或资料管理目标。

## 包内入口

`scripts/media-index.py`随包提供，仅用Python标准库；可选调用当前宿主已有ffprobe。无需外部媒体Skill、连接器、本地MCP或后台常驻服务。Python不可用时可先使用`material-inventory.mjs`盘点并说明本轮未执行SQLite索引；不要自动安装运行环境。

在宿主已经解析本包路径后查看接口和内存自检：

```text
python -I -B <本包脚本路径>/media-index.py --describe
python -I -B <本包脚本路径>/media-index.py --self-test
```

占位符须由当前用户任务的真实路径替换；在任意cwd调用时使用带引号的绝对脚本路径。`-I -B`隔离Python环境并禁止生成包内字节码。执行用户任务时使用该工具，不重新手写一个固定本机路径的索引器。

## 授权与读写范围

`build --source-root <素材根> --index-root <独立索引根>`默认只盘点文件元数据。`--probe`明确启用ffprobe读取格式信息；`--hash`明确启用整文件SHA-256与MD5分块读取。哈希不等于内容理解，也不等于原件前后未改动的独立证明。素材、索引根必须互不包含；索引根首次必须不存在，后续仅允许使用本工具创建且来源一致的索引。原视频永远按只读打开。

默认限制为100000个遍历条目、16GiB哈希读取预算、600秒总时间，每个ffprobe最多30秒、stdout最多1MiB、stderr最多64KiB。可通过`--max-entries/--max-hash-bytes/--max-seconds`在当前任务范围内调整。容量字段同时给出原始bytes、十进制GB和二进制GiB，不能混用。视频大小超过可用预算时先分批或调整预算，不把整个视频编码为base64放入对话。

## 完整扫描与增量

每次build必须完成素材树遍历，并在处理后再次核对文件集合、大小和时间。根不可用、目录无权限、链接、读取预算超限、文件变化均阻止新当前索引发布。历史成功索引保持可读；失败的候选文件保留在本轮索引根内以便诊断。

每个成功发布均形成独立SQLite文件、对应回执及`CURRENT.json`。只用一个排他写锁，第二个写者不得清除已有锁；进程异常留下锁时由人工核验后处理，或新建索引根，不自动推定旧锁无主。索引的旧版本不会自动清理。这些机制是本地文件快照和原子指针发布，不宣称跨设备事务或断电恢复已验证。

无变化且请求的探测/哈希均已成功的文件跳过重复处理。探测失败项即使size和mtime不变也会再次尝试；非零退出、坏JSON、无有效视频流和未知时长会留下明确失败状态。扫描完整但部分探测失败可发布带`partial`回执的索引，CLI返回exit2，不能报告全量元数据成功。所有未知时长保持null，不补成0并算入完整时长覆盖。

## 检索和导出

- `search --index-root <索引根> 微信 视频`使用逐词AND组合：3字符及以上走trigram，1–2字符走LIKE。短词不因同时有长词而被忽略。FTS不可用时使用逐词LIKE并记录实际引擎。
- 过滤包括`--group/--month/--year/--codec/--longer/--shorter/--min-bytes/--max-bytes/--duplicates/--errors`。时长单位为秒、容量筛选单位为bytes。空关键词时明确区分全量和仅条件过滤。
- search默认最多返回100条，最多可指定1000条；输出total/returned/omitted。`stats --index-root <索引根>`给出总量与覆盖率。
- `export --index-root <索引根> --output <新文件名.csv> ...`导出全部命中结果，输出仅能位于索引根的exports目录，已有文件不得覆盖；不能把素材文件或任意外部路径设为导出目标。CSV可能被电子表格解释为公式的文本会加转义前缀。
- 重复候选以整文件SHA-256分组，可释放容量按每组总容量减保留一份计算。工具不删除原件；未全部哈希时必须注明重复覆盖不完整。

search/stats只打开已发布SQLite快照的只读连接，不创建库或修改索引。结果、回执和导出文件应按实际写入目标回读；工具返回completed不等于命令exit0。CLI成功exit0，部分或阻断exit2。

## 从索引到长文档

元数据只能检索文件名、路径、年月、格式等。画面中的人物、事件、文字与对话，需要WorkBuddy当前可用的视觉、OCR/ASR或解析工具提供真实派生产物，再进入证据链。无需为此绑定某一个宿主模型或媒体Skill。

按目标章节、年代、编码、音轨和内容价值选择代表性小样，时间长不是唯一排序标准。派生记录至少包含：源文件摘要、片段起止秒、处理工具/模型及参数、实际读取范围、原始观察或转写、校订依据、置信/未知项、覆盖残余。短视频也可能含关键事实，不按时长阈值永久排除。

把片段观察接入现有`ModalityReceipt`和`evidence-packet.mjs`来源包，经人工或独立来源核对后，再形成事实、人物/事件线索与章节引用。索引成功不直接将画面理解、逐字稿、全文写作或宿主验收标成完成。来源、处理中间件、包内可复用工具和当场生成代码各自记录归属。
