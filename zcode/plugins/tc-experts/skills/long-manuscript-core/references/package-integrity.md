# 包完整性与安装态健康

本专家把提交归档的物理字节真相和宿主安装后的可执行内容真相分开证明。两者不能互相替代。

## 两层证据

- `archivePhysicalManifest` 对提交候选中的每个载荷文件绑定原始字节数、原始 SHA-256 和确定性的原始文件树摘要。ZIP、二进制、用户材料、事务输入和回执始终使用原始字节哈希。
- `installedRuntimeReceipt` 把一个已知归档清单与一个安装目录比较。包内文本采用 `sha256_utf8_lf_v1`，只将 CRLF 或 CR 归一化为 LF；严格 UTF-8，拒绝 BOM。二进制仍比较原始字节。
- `.codebuddy-plugin/plugin.json` 允许宿主只改变换行和 JSON 属性顺序，其安装态绑定使用 `canonical_json_utf8_v1`。字段、数组顺序、值或类型变化仍属于实质变化。
- `FILE-MANIFEST.sha256.json` 保持 `raw_package_entry_bytes` 语义。安装器改变换行后，它预期会报告原始字节不一致；不得把这个失败改写成原始清单通过。只有来自同一归档真源的安装态内容树回执通过，才可把差异归类为允许的宿主转换。

## 失败关闭

以下任一情况阻止安装态回执：字符或脚本逻辑变化、尾随空格、BOM、非法 UTF-8、缺失或额外文件、路径逃逸、二进制变化、场景或质量注册表损坏，以及场景或评估器运行时不可用。

单场景或单评估器损坏必须被隔离：无关场景和其余评估器仍可诊断，但总体健康为 `degraded`，目标场景不得静默回退，损坏评估器不得被伪装成已执行。

## 只读健康检查

`scripts/runtime-health.mjs` 只读包目录，输出计数、状态、相对路径和错误码；不输出文档正文、材料摘录、凭据或服务流量。没有外部提供且深度校验通过的 `archivePhysicalManifest` 时，健康检查只能返回未锚定的降级诊断，安装目录及其内嵌清单不得为自身作证。审核方必须从同一候选 ZIP 的物理 SHA-256、字节数、根目录、条目集合和 `FILE-MANIFEST.sha256.json` 物理身份建立归档锚，才可生成 `installedRuntimeReceipt`。

外部验证器必须先按归档锚静态校验健康脚本及其核心依赖，再导入包内代码。32 个叶评估器只有在其摘要通过后才允许动态导入，并逐一核对 `gateId`、`evaluate`、`validate` 导出和一次无外部动作的最小调用；核心脚本实质变化时不执行待审代码。

仅包根目录允许出现一个 `.downloaded_at` 宿主私有元数据文件：健康检查只记录其存在与字节数，不读取内容，也不把它纳入包载荷或安装态内容树。任意子目录中的同名项均为完整性错误。
